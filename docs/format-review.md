# Ревью найденных форматов

Локальный инструмент для одной партии: агент готовит данные, пользователь редактирует поля и отмечает нужные записи, затем копирует выбранное для таблицы или обратно агенту.

## Скилл для подготовки и продолжения

Скилл [Import Formats](../.agents/skills/import-formats/SKILL.md) связывает сбор из источника, сравнение с каталогом, создание HTML и обработку решения после ревью. На этой машине он также подключён в личную папку скиллов Codex. Достаточно короткого запроса:

```text
$import-formats Собери форматы из [ссылка на чат, сайт или файл].
```

Агент использует существующий шаблон, сохраняет отдельную подборку в `ignore/format-review/` и выдаёт ссылку на HTML. После этого он ждёт следующего сообщения, без фонового ожидания. В `review-state.json` остаются пути к файлам, источник, охват просмотра и состояние, чтобы продолжить позже.

После ревью нажмите «Скопировать для агента» и пришлите результат в тот же чат. Для записи явно укажите, что выбранные операции нужно применить к таблице; подготовка HTML сама по себе запись не разрешает. Скилл проверяет решение относительно исходной подборки, а перед разрешённой записью — свежие значения изменяемых полей. Код проверки JSON находится в скилле, отдельного средства автоматической записи в таблицу он не добавляет.

## Входные данные

Пример: [example-batch.json](../tools/format-review/example-batch.json). Входящие форматы и их источники вымышленные; для сравнения приложен снимок реальной «Пресс-конференции» из каталога со ссылкой на неё. В примере описание черновика совпадает с исходным текстом, неподтверждённые признаки остаются неизвестными.

У партии обязательны `schemaVersion: 1`, `kind: "format-review-batch"`, непустой `batchId` и массив `candidates`. Необязательный `title` задаёт заголовок HTML. Пустая партия допустима.

Необязательный `classificationOptions` содержит три массива строк `forms`, `features`, `collections` — существующие варианты для селекторов. Это открытый список: пользователь может выбрать имеющиеся значения, убрать выбранные или создать новый тег отдельным действием. Значения из кандидатов также доступны в списках.

Каждый кандидат содержит:

- `candidateId` — непустой уникальный идентификатор внутри партии, не постоянный id каталога.
- `format` — все поля из таблицы ниже.
- `source` — непустая подпись `label`, необязательные `url` и исходный `text`.
- `similarFormats` — необязательный массив снимков похожих существующих форматов. У каждого обязательны `id`, `title`, `description`, `reason`. В `reason` агент одной короткой фразой называет общую механику и решающее различие, дополнение или конфликт; не пересказывает оба описания и общую политику импорта. Описание сохраняется в HTML, поэтому его можно читать без сети.
- `recommendation` — необязательные рекомендуемое действие, причина и предлагаемые дополнения. Скилл заполняет его для каждой находки после сравнения с каталогом.

Для полного сравнения у совпадения передаются `moderator`, `audienceOnStage`, `props`, `furniture`, `note`, `forms`, `features`, `collections`, `video` с теми же типами, что у черновика. Необязательный `url` задаёт ссылку на существующий формат; без него ссылка строится по постоянному id на impro-formats.vercel.app. Прежние снимки из четырёх полей поддерживаются: отсутствующие значения показываются как «Не передано», а не как отрицательные или пустые. Флаг `--catalog` заполняет варианты тегов; сами совпадения берутся из `similarFormats` партии.

| Поля `format` | Тип |
| --- | --- |
| `title`, `description`, `furniture`, `note` | Строки; название выбранной записи должно быть непустым |
| `moderator`, `audienceOnStage`, `props` | `true`, `false` или `null` (неизвестно) |
| `forms`, `features`, `collections` | Массивы непустых строк, пустой массив допустим |
| `video` | Обычный текст: название видео или пояснение и URL на одной строке, отдельная строка для каждого видео; в прежних партиях отсутствие поля даёт пустую строку |

У добавляемой видеоссылки указывайте название ролика или короткое пояснение, что зритель увидит, например `Без буквы — пример игры: https://…`. Если подписи нет в источнике, откройте страницу видео и проверьте название, описание или превью. Если страница недоступна, используйте только подтверждённый контекст источника и зафиксируйте ограничение проверки; не придумывайте название. В сообщениях с несколькими форматами проверьте привязку каждой ссылки. Исходный текст, снимки каталога и прежние записи поля «Видео» сохраняйте дословно; новые ссылки с подписями добавляйте без повторения уже имеющихся URL.

Агент предзаполняет требования по смыслу правил, даже если отдельного списка требований в источнике нет: нужен ли модератор, зритель на сцене, реквизит и мебель. Когда описанная механика явно обходится без них, ставит `false` и мебель `"Нет"`. Например, сцена четырёх актёров с постоянными эмоциями не требует этих четырёх условий. Зрительская подсказка из зала сама по себе не означает зрителя на сцене; роль ведущего внутри сцены не обязательно требует отдельного модератора.

Одного отсутствия упоминания недостаточно: если из неполного или неоднозначного описания нельзя сделать вывод, признак остаётся `null`, текст и списки — `""` и `[]`. Генератор сам не превращает пустые значения в «Нет». При обновлении заполненные данные каталога сохраняют приоритет над предположениями агента. Поля `format`, кроме совместимого с прежними партиями `video`, обязательны; постоянного `id`, `searchText` и `furnitureKinds` у кандидата нет. Неизвестные поля и неверные типы вызывают ошибку с путём к полю.

В `note` («Дополнительно») **никогда не добавляйте общую продолжительность формата или раунда**, в том числе указанную в регламенте школы/сезона, — ни для новой записи, ни как дополнение к существующей. Это правило подготовки данных агентом, а не автоматическое удаление текста редактором. Временные ограничения, определяющие саму механику (например, повтор сцены за 60 → 30 → 15 секунд), сохраняются в правилах. Исходный текст и снимок каталога остаются дословными.

Сбор из источников и поиск совпадений выполняются агентом до подготовки HTML. Отсутствие подсказок не означает, что дублей нет. Реальные JSON и HTML храните в `ignore/format-review/` или другом непубличном месте; не добавляйте в них ключи доступа.

## Рекомендуемые действия

Единые значки и подписи на карточках определены в `REVIEW_RECOMMENDATIONS` общей модели, а не выбираются агентом произвольно. Отдельной легенды на странице нет. В `recommendation` обязательны `action` и непустой `reason`: одна короткая фраза с причиной решения или конкретным вопросом. Не повторяйте описание формата и общие правила импорта; комментарии к отдельным совпадениям тоже должны быть краткими. Причины показываются без префикса «Агент:».

Карточки при открытии группируются по рекомендации: добавить → обновить → проверить → пропустить → дубли. Без рекомендации карточка попадает в группу проверки. Внутри группы сохраняется исходный порядок. Редактирование и смена режима не перемещают карточку; выгрузки сохраняют исходный порядок партии.

| Действие | Метка | Начальное состояние |
| --- | --- | --- |
| `create` | ➕ Добавить | Выбрана новая запись |
| `update` | 🔄 Обновить | Выбрано обновление указанной цели с предложенными значениями полей |
| `duplicate` | 🟰 Дубль | Не выбрана; отдельная цветная метка «Дубль» |
| `skip` | ⏭️ Пропустить | Не выбрана: например, нет описания формата |
| `review` | ❓ Проверить | Не выбрана: решение требует внимания пользователя |

У `update` обязательны `targetId` из `similarFormats` и непустой `changes` — конечные значения только реально изменяемых полей, без обёртки before/after. У `duplicate` обязателен `targetId`, изменений нет. Остальным действиям цель и изменения не передаются. Пример:

```json
{
  "action": "update",
  "reason": "Есть новое видео; описание и заполненные признаки каталога сохраняем.",
  "targetId": "press-konferentsiya",
  "changes": {
    "video": "https://example.com/old\nhttps://example.com/new"
  }
}
```

Рекомендация обновления требует полного снимка цели. Пустые значения, null, противоположный заполненному признак, удаление прежних тегов или видео отклоняются. Массивы и видео в `changes` должны включать прежние значения и полезные дополнения. Если находка описывает тот же формат, но содержит меньше данных, выбирайте `duplicate`: отсутствие сведений не является обновлением. При противоречии заполненным данным нужен `review`, а не автоматическая замена. Приоритет у данных каталога; агент предлагает дополнения к ним.

Пользователь может изменить галочку, поля и режим. Рекомендация остаётся видимой как контекст, а в выгрузку идёт текущее решение. Защита рекомендованных изменений не запрещает явные ручные правки, включая очистку. Без `recommendation` сохраняется прежнее поведение: новый формат и снятая галочка.

Изменение поля, тега или перенос значения из находки автоматически выбирает карточку и обновляет счётчик. Галочку можно снять вручную; следующая правка снова её поставит. Открытие карточки, фокус на поле и переключение режима сами по себе выбор не меняют.

Готовый [пример с рекомендациями](../tools/format-review/example-recommendations.json) показывает добавление, обновление, дубль и проверку. Источники вымышленные; рекомендация обновления демонстрирует сохранение описания и признаков каталога.

## Создание HTML

Из корня проекта:

```bash
npm run review:generate -- --input tools/format-review/example-batch.json
```

Результат: `ignore/format-review/review.html`. Откройте файл в обычном браузере двойным кликом. Сервер, сеть и ключи не нужны. Для отдельной партии можно задать путь:

```bash
npm run review:generate -- --input ignore/format-review/batch.json --output ignore/format-review/telegram-review.html
```

Вывод в `public/` и `dist/` проекта запрещён. Некорректный входной JSON не заменяет уже созданный HTML.

Если `classificationOptions` не задан, генератор берёт варианты из локального `public/data/formats.json`. Для актуального снимка рабочего каталога можно указать `--catalog ignore/format-review/catalog.json` (JSON версии 2 или 3). При таком запуске в HTML попадают только варианты классификации, а не все записи каталога. Чтение таблицы выполняет агент отдельно; готовый HTML и генератор не требуют доступа к сети или ключей.

### Аннотирование в Codex

Для замечаний по интерфейсу открывайте HTML во встроенном браузере Codex по локальному HTTP-адресу и нажимайте **Annotate / «Аннотировать»** в панели браузера. Такой способ проверен пользователем; исключение файла из Git ему не мешает. Документация: [Browser](https://learn.chatgpt.com/docs/browser).

Для просмотра скопируйте только готовый HTML в `review-preview.local/review.html`. Эта папка находится вне `ignore/` и исключена из Git правилом `*.local`; исходная партия и её состояние остаются в `ignore/format-review/`. Запустите из корня проекта:

```bash
python3 -m http.server 4186 --bind 127.0.0.1 --directory review-preview.local
```

Откройте `http://127.0.0.1:4186/review.html` через `open_in_codex` с целью `browser` или вручную во встроенном браузере. Сервер должен оставаться запущенным во время просмотра; он обслуживает только папку превью. Папку `ignore/` с исходниками и учётными данными не нужно открывать через Vite. При следующем обновлении заменяйте копию HTML актуальной версией.

## Как просматривать

Основной сценарий — работа с компьютера: сравнение описаний, редактирование полей и выбор записей.

Совпадения объединены одним заголовком «Похожие форматы в каталоге» со счётчиком. Внутри каждый блок подписан только названием существующей записи: подпись «В каталоге» над каждым совпадением не повторяется.

1. Категории «Добавить», «Обновить», «Проверить», «Дубли» и «Пропустить» со счётчиками фильтруют список. Категории определяет рекомендация агента; ручные решения не перемещают карточки. «Все» возвращает полный список. Массовый выбор, снятие выбора и раскрытие действуют только на видимые карточки.
2. Нажмите название или стрелку карточки. Сначала видны название и описание импортируемого формата единым блоком, затем — похожая запись из каталога. Рекомендованная цель (или первое совпадение) сразу раскрыта, остальные раскрываются независимо. «Параметры и ссылки» показывают требования, теги, заметки, видео и id. Отдельного блока «Исходник» нет: рядом с находкой остаётся ссылка, дословный текст сохраняется в партии и выгрузке.
3. «Редактировать» открывает поля вместо блока находки, «Готово» возвращает читаемую карточку. Правки автоматически выбирают запись. «Добавить» / «Добавить как новый» явно выбирает создание, «Снять выбор» исключает операцию из выгрузки. Подпись рядом с действиями показывает текущее решение отдельно от рекомендации агента.
4. Основная кнопка «Скопировать для агента» передаёт все выбранные добавления и обновления, в том числе скрытые фильтром и свёрнутые. Счётчик показывает общее количество и разделение на новые записи и обновления. «Скопировать новые для таблицы (N)» берёт только новые строки. Выгрузки используют текущие правки в исходном порядке партии.

Поля подписаны «Название» и «Описание». В тегах доступны выбор существующих значений, удаление и «Новый тег…». «Неизвестно» у признака отличается от «Нет». Исходник и снимки каталога сохраняются дословно. Если пустое название выбранной записи мешает копированию, страница снимает фильтр, раскрывает редактор и переводит фокус к полю.

Правки и галочки автоматически сохраняются после изменения и восстанавливаются после перезагрузки или повторного открытия в том же браузере по тому же адресу. Сохраняются и невыбранные записи, отдельные черновики создания и каждой цели обновления, новые теги, метки ручных правок, открытые редакторы и категория. Статус сохранения виден над списком. Это локальный черновик браузера; страница не записывает ничего в таблицу и не запускает Publish.

«Сбросить правки» запрашивает подтверждение, удаляет сохранение текущей подборки и возвращает исходные поля, рекомендации и начальный выбор. Черновики других подборок и настройка ширины остаются. Отмена и Escape сохраняют текущую работу.

«↺ Сбросить» в заголовке раскрытой карточки возвращает только этот формат к исходным полям, рекомендации и начальному выбору, включая все его черновики создания и обновления. После подтверждения карточка остаётся раскрытой, результат автоматически сохраняется. Другие карточки, их правки и выбор, общие варианты тегов и текущая категория сохраняются.

Кнопка карточки видна только при отличии полей от начальных значений хотя бы в одном её черновике. Изменение галочки, переключение между созданием и обновлением и исходное предложение агента правками не считаются. Если вручную вернуть все поля к начальным значениям или выполнить сброс, кнопка исчезает.

При недоступном или переполненном хранилище редактор продолжает работать, показывает ошибку сохранения и предупреждает при уходе с несохранёнными правками; результат можно скопировать. Повреждённое сохранение, несовпадение исходной подборки или более новая запись другой вкладки не применяются и не перезаписываются молча. Сохранения разделены по `batchId` и проверяются по исходным кандидатам; при изменении исходных данных требуется явный сброс. Перегенерация только интерфейса сохраняет совместимость черновика.

Когда курсор находится над карточкой, **C** переключает её раскрытие, **S** — выбор. Подсказка в общей панели не показывается; клавиши сохранены в подсказках отдельных контролов. Используются физические клавиши, поэтому русская раскладка тоже подходит. Горячие клавиши не работают при фокусе в текстовом поле или селекторе, во время ввода через IME, в окне ручного копирования и с модификаторами. Удержание клавиши не повторяет действие.

Ширина по умолчанию ограничена 1054 px. Перетащите правый край списка, чтобы сузить или расширить панели; шапка и нижняя панель выравниваются с ними. На крае также работают стрелки ←/→, Home/End; двойной клик возвращает ширину по умолчанию. Настройка сохраняется в браузере, если локальное хранилище доступно. Ширина ограничивается экраном и не влияет на правки и выбор.

## Обновление существующего формата

Рекомендованное обновление уже содержит предлагаемые изменения. Для ручного выбора нажмите «Подготовить обновление» у нужного совпадения. Это открывает редактор локального черновика; каталог не меняется. Строка действия показывает выбранную цель и число изменённых полей; переход к обновлению сам по себе галочку не ставит, первая правка выбирает запись.

Сразу после описания находки видна **выбранная запись каталога**, остальные совпадения сворачиваются и идут за ней. Следом расположен редактор «Сравнение полей»: сразу видны отличия находки от каталога и уже изменённые поля итога. Просмотр отличий сам по себе не меняет итог и не выбирает формат. Счётчик «Изменено полей» учитывает только правки итога относительно каталога. Каждая строка объединяет три значения: **Находка / В каталоге / Итог**. Группы полей отделены заголовками и отступами; группы без видимых полей скрываются. Итог редактируется; «Показать все поля» раскрывает полный формат, «Только различия» возвращает краткий вид. Поле, которое вы только что вернули к исходному значению, остаётся видимым до явного переключения вида.

Различающиеся строки выделены тёплым фоном и отметкой «≠ Различается»: это отличие находки от каталога или итога от каталога, включая пустые значения. Подсветка не объявляет отсутствие данных конфликтом. Зелёным отмечены источники итогового значения, без дублирующих меток над итогом. Если находка, каталог и итог одинаковы, подсвечены оба источника, а кнопок переноса и подписей «В итоге» нет. При изменении итога появляются отличия и действия возврата. Над итогом остаются только «Предложение» и «Ручная правка», когда значение отличается от обоих источников и их объединения. У каталога кнопка «Взять» возвращает только это поле. Эти отметки не меняют состав выгружаемых полей.

Перенос из находки выполняется по полю:

- **«Добавить»** у видео сохраняет текущий текст и дописывает отсутствующие непустые строки. У формы, особенностей и подборок добавляются отсутствующие теги.
- **«Заменить»** у остальных полей заменяет только выбранное значение, включая явно выбранное пустое или неизвестное значение. Итог после переноса можно поправить вручную.

Находка содержит ваши правки до перехода к обновлению. Исходный снимок каталога сохраняется отдельно. При отсутствии изменений доступна кнопка полного редактора. Неполный снимок не допускает обновления; отсутствующее поле обозначается «Не передано».

«Добавить как новый» возвращает черновик новой записи и выбирает его для выгрузки. Черновики создания и каждой цели обновления сохраняются отдельно. Постоянный id цели не зависит от редактирования названия. Выбранное обновление без изменений и несколько выбранных обновлений одного id блокируют агентскую выгрузку с объяснением.

Обновления передаются только агенту и исключаются из табличного копирования. Если выбраны только обновления, кнопка новых строк недоступна.

## Что совпало у дубля

В раскрытом дубле сначала видны название и описание импортируемого формата одним блоком. Сразу за ним — название и полное описание рекомендованной записи каталога, без промежуточного «Исходника» и вложенной панели «Похожие форматы». Дополнительные параметры и редактор открываются по запросу. Короткие причины сходства и рекомендации остаются рядом с соответствующим блоком.

Наведение или клавиатурный фокус на «Параметры ≠ N» показывает всплывающую таблицу только несовпадающих известных параметров: название, значение находки и значение каталога. Подсказку можно закрыть Escape; она не меняет поля и выбор.

В шапке дубля, включая свёрнутую карточку, показаны три короткие отметки относительно `recommendation.targetId`: «Название», «Описание», «Параметры». Совпадение — зелёная подпись с ✓, различие — оранжевая с ≠; у параметров рядом указано число известных отличий. Неполные и неизвестные данные — нейтральная подпись с ?. Пояснения доступны при наведении и для чтения с экрана. Отметки сравнивают исходную находку со снимком цели и не меняются от ручных правок черновика.

Для описания агент передаёт `recommendation.descriptionMatch`: `equivalent` (те же правила по смыслу), `different` (правила отличаются), `unknown` (не оценено). Поле допустимо только для дубля, необязательно для прежних партий. Дословное непустое описание определяется автоматически; без оценки агента разные тексты не объявляются совпавшими.

Название сравнивается без учёта регистра и лишних пробелов. Параметры — модератор, зритель на сцене, реквизит, мебель и три группы тегов; порядок тегов не важен. `null`, пустые строки/списки и отсутствующие значения не считаются совпадением или отличием. Подсказка у параметров перечисляет результат для каждого поля; «частично (N/7)» в ней означает N совпавших параметров при неизвестных остальных. Заметки и видео не относятся к этим семи параметрам. Оценка сохраняется в агентской выгрузке как контекст; TSV не меняется.

## Два варианта копирования

**Для таблицы:** копируются только выбранные новые форматы. Вставляйте в первую пустую строку листа «Все форматы», начиная с **колонки A**, без входа в режим редактирования отдельной ячейки. Заголовок не копируется. Строка содержит 12 ячеек в порядке A–L, последняя — «Видео», например:

```json
["", "Новый формат", "Правила игры", "", "FALSE", "TRUE", "Два стула", "", "Короткая форма", "Музыкальные", "", "https://example.com/video"]
```

В буфере эти ячейки разделены табуляцией (TSV); первая ячейка `id` пуста. Несколько выбранных форматов дают несколько строк. Кавычки, табуляция и переносы внутри текста экранируются. Перед текстом, начинающимся с `=`, `+`, `-`, `@` или апострофа (в том числе после пробелов), добавляется защитный апостроф. В некоторых редакторах он остаётся видимым; это часть табличного транспорта, исходный текст в карточке и JSON не меняется. Постоянный id новой строки назначит существующий Publish.

**Для агента:** результат имеет `schemaVersion: 2` и явный `action` у каждого элемента. Новые записи (`create`) содержат `format`. Обновления (`update`) содержат постоянный `targetId`, исходное имя `targetTitle` и только изменённые поля в `changes`, у каждого значения есть `before` и `after`. У обновления нет `format`, чтобы оно не выглядело новой строкой. Пример создания:

```json
{
  "schemaVersion": 2,
  "kind": "format-review-selection",
  "batchId": "example-batch",
  "candidates": [
    {
      "candidateId": "example-1",
      "action": "create",
      "format": {
        "title": "Новый формат",
        "description": "Правила игры после редактирования",
        "moderator": null,
        "audienceOnStage": false,
        "props": true,
        "furniture": "Два стула",
        "note": "",
        "video": "",
        "forms": ["Короткая форма"],
        "features": ["Музыкальные"],
        "collections": []
      },
      "source": { "label": "Вымышленный источник" }
    }
  ]
}
```

Пример элемента обновления:

```json
{
  "candidateId": "example-2",
  "action": "update",
  "targetId": "press-konferentsiya",
  "targetTitle": "Пресс-конференция",
  "changes": {
    "video": {
      "before": "https://example.com/old",
      "after": "https://example.com/old\nhttps://example.com/new"
    }
  },
  "source": { "label": "Вымышленный источник" }
}
```

Если агент передал `similarFormats`, они сохраняются у выбранных кандидатов. JSON описывает решение пользователя, а не факт добавления или публикации. Сам инструмент не даёт агенту права записывать в исходную таблицу: для записи нужны отдельное поручение пользователя и соблюдение правил проекта.

Если браузер отклоняет автоматическое копирование, появляется окно с выделенным текстом для ручного копирования (`⌘C` / `Ctrl+C`). Закрыть окно можно крестиком или Escape; правки и галочки сохранятся.

## Короткая инструкция агенту

1. Собери одну партию по входной схеме. Сохрани исходный текст дословно. Черновик можно структурировать и сокращать, но не добавлять неподтверждённые правила и признаки. Для совпадений приложи полный снимок полей, видео, постоянный id, ссылку и объяснение сходства и отличий. Заполни `recommendation`: новые сведения — create/update, тот же формат без полезных дополнений — duplicate, неподходящее — skip, сомнение — review. Поля каталога имеют приоритет; пустота в находке не является изменением.
2. Сохрани JSON в `ignore/format-review/` и запусти `review:generate` с отдельным именем HTML. Передай пользователю абсолютный путь к готовому файлу.
3. Получив `format-review-selection` версии 2, различай `create` и `update`. При обновлении найди запись по `targetId`, прочитай свежие значения изменяемых полей и сравни с `before`. При расхождении покажи конфликт; не применяй такую правку молча. Если значения совпадают, после отдельного поручения на запись меняй только поля из `changes` на `after`, включая явно выбранные пустые значения. Остальные поля и id сохраняются; обновление не добавляется новой строкой и не запускает Publish.
4. Для повторного ревью собери входную партию версии 1 заново. У `create` можно взять `format`, источник и совпадения, убрав `action`; для обновления нужен полный исходный снимок цели. Простая замена `kind` у выгрузки версии 2 недостаточна.
