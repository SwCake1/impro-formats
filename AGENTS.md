# Impro Formats

Статический каталог на Vite + TypeScript. Браузер читает `data/formats.json` со своего сайта.

Схема: ручной `Publish` в Apps Script → снимок значений на листе «Опубликовано» → чтение через Sheets API при сборке Vercel.

`npm run build:published` получает и проверяет одобренный снимок, собирает сайт и записывает публичные данные в `dist`. Настройки — серверные переменные `GOOGLE_SHEET_ID` и `GOOGLE_SERVICE_ACCOUNT_JSON` либо локальный путь `GOOGLE_APPLICATION_CREDENTIALS`. Ошибки импорта останавливают сборку. Обычная `npm run build` пока использует фиксированный `public/data/formats.json` для GitHub Pages. Команда сборки Vercel и HTTP-кэш заданы в `vercel.json`. Сайт опубликован на https://impro-formats.vercel.app/ ; каталог и HTTP-кэш проверены. Publish запускает сборку через Deploy Hook, вся цепочка проверена.

`npm run dev` читает рабочий лист «Все форматы» через локальный сервер при каждом запросе каталога. `npm run dev:published` читает лист «Опубликовано», `npm run dev:cached` использует файл `public/data/formats.json` без Google API. Учётные данные остаются на сервере; источники имеют отдельные браузерные кэши. Ошибка чтения таблицы не подменяется файлом. Локальный сервер не записывает и не вычисляет id; новые строки без id требуют Publish. Браузерные тесты используют `dev:cached`.

Каталог — обычный JSON. Браузер сразу показывает проверенный локальный кэш, затем проверяет HTTP-кэш у сервера. Совпавший ETag позволяет повторно использовать записи. Ошибка сети, новых данных или хранилища не должна удалять рабочий каталог.

Схема публикации A–K содержит независимые колонки «Форма», «Особенности», «Подборки» и выдаёт JSON версии 3 с массивами `forms`, `features`, `collections`. Прежний JSON и кэш версии 2 поддерживаются для плавного обновления сайта. Варианты фильтров берутся из данных; особенности объединяются через «И», подборки — через «ИЛИ», разные группы — через «И».

Локальные учётные данные могут находиться в `ignore/`: папка исключена из Git и закрыта для сервера Vite. Ключи не должны попадать в клиентский код, `public/` или коммиты.

Apps Script вызывает Deploy Hook после сохранения и `flush()` снимка.
URL читается только из свойства скрипта `VERCEL_DEPLOY_HOOK_URL`; перед записью проверяется адрес Vercel.
Ошибки запроса не должны раскрывать URL или выдавать сохранение снимка за успешный запуск сборки.
Версия перенесена в Apps Script, свойство настроено, реальная публикация подтверждена 25.10.2026; прогресс отмечен в плане.

## Правила

- Не редактировать исходную Google-таблицу.
- Сборка и браузер используют постоянные `id` из первой колонки таблицы, без повторного вычисления из названия или описания.
- При первом Publish новые строки с пустым `id` получают транслитерацию названия: «Новый формат» → `novyy-format`, при совпадениях добавляются `-2`, `-3` и т. д. Все данные и настройка хука проверяются до записи id в рабочий лист; id сохраняются перед снимком. Существующие id не переписываются, в том числе при переименовании; повторы и некорректные заполненные id считаются ошибкой. При сбое публикации уже записанные id остаются для повторной попытки.
- Сохранять `base: './'`, чтобы сайт работал в подпапке GitHub Pages.
- Данные таблицы выводить только как текст, без небезопасного HTML.
- Пустые признаки считать неизвестными, а не отрицательными.
- Интерфейс должен работать с клавиатуры и на мобильных экранах.
