# format-review Specification

## Purpose

Позволяет просмотреть одну подготовленную агентом партию форматов, исправить поля и выбрать записи для переноса. Сохраняет связь с источниками и подсказками о совпадениях при передаче результата обратно агенту.

## Requirements

### Requirement: Explain duplicate agreement concisely
Дубль MUST показывать в шапке, включая свёрнутую карточку, сравнение названия, описания и параметров исходной находки с рекомендованной целью. Описание MUST сравниваться по тексту или переданной оценке агента. Отметки MUST различать совпадение, отличие и недостаток данных; пустые значения MUST NOT считаться совпадениями. Сравнение MUST оставаться контекстом, не меняя выбор и черновики.

#### Scenario: See the imported description before existing matches
- **WHEN** пользователь раскрывает дубль
- **THEN** название и описание находки видны одним блоком сразу под шапкой, за ними — раскрытая рекомендованная запись каталога без промежуточного исходного текста

#### Scenario: Same mechanics with a different name and incomplete parameters
- **WHEN** агент помечает находку дублем с equivalent, название другое, часть параметров совпадает, а остальные неизвестны
- **THEN** свёрнутая карточка показывает оранжевое «Название ≠», зелёное «Описание ✓» и нейтральное «Параметры ?»; пояснения доступны при наведении и для чтения с экрана, неизвестные значения не засчитываются

#### Scenario: Show compact difference counts
- **WHEN** у дубля совпадает название и описание, а два известных параметра отличаются и остальные совпали или неизвестны
- **THEN** карточка показывает зелёные «Название ✓» и «Описание ✓», оранжевое «Параметры ≠ 2»; пустые значения не увеличивают число отличий

#### Scenario: Inspect parameter differences on hover or focus
- **WHEN** пользователь наводит курсор или клавиатурный фокус на «Параметры ≠ N»
- **THEN** появляется таблица несовпадающих известных параметров со значениями находки и каталога; она доступна при наведении на саму таблицу и закрывается Escape, не меняя выбор и правки

#### Scenario: Preserve compatibility and review context
- **WHEN** партия не содержит descriptionMatch или пользователь редактирует дубль и копирует выбранное решение
- **THEN** без оценки разные описания показаны как неоценённые; исходное сравнение не пересчитывается по черновику, переданная оценка сохраняется в JSON, схема TSV остаётся прежней

#### Scenario: Compare known parameters and accept explicit semantic assessment
- **WHEN** передана оценка `recommendation.descriptionMatch` (equivalent/different/unknown), а название и семь параметров (три признака, мебель, три классификации) сравниваются с целью
- **THEN** оценка допустима только для дубля; известные значения сравниваются без учёта регистра, лишних пробелов и порядка тегов, неизвестные значения исключаются из совпадений, отличия отмечаются явно

### Requirement: Generate a standalone review file
Инструмент MUST принимать JSON партии по документированной версионированной схеме и создавать автономный HTML, открываемый как локальный файл без сервера и автоматических сетевых запросов. Некорректные данные MUST приводить к понятной ошибке без создания или перезаписи результата.

#### Scenario: Open a prepared batch locally
- **WHEN** агент генерирует HTML из корректной партии и пользователь открывает файл без сети
- **THEN** отображаются все кандидаты и доступны редактирование, выбор и подготовка обеих выгрузок

#### Scenario: Reject invalid input
- **WHEN** JSON содержит неподдерживаемую версию, повторяющиеся идентификаторы кандидатов или поля неверного типа
- **THEN** генерация завершается с ошибкой, указывающей проблемное поле, а существующий выходной файл остаётся прежним

#### Scenario: Review an empty batch
- **WHEN** партия не содержит кандидатов
- **THEN** HTML сообщает, что форматов нет, и не предлагает копирование пустого результата

### Requirement: Edit catalog fields without changing unknown values
Редактор MUST позволять менять название, описание, признаки модератора, зрителя на сцене и реквизита, мебель, дополнительно, форму, особенности, подборки и видео. Признаки MUST различать «Да», «Нет» и «Неизвестно». Правки MUST сохраняться в течение открытого сеанса при переходе между кандидатами.

#### Scenario: Edit several candidates
- **WHEN** пользователь меняет текст и классификацию одного кандидата, открывает другого и возвращается
- **THEN** отображаются внесённые правки, включая переносы строк и изменённые списки

#### Scenario: Preserve an unknown flag
- **WHEN** у кандидата признак имеет значение null и пользователь его не меняет
- **THEN** редактор показывает «Неизвестно», а экспорт сохраняет неизвестное значение

### Requirement: Explicitly select candidates for export
Начальный выбор MUST следовать переданной рекомендации: добавление и обновление выбраны, дубль, пропуск и проверка не выбраны. Без рекомендации кандидат MUST быть не выбран. Пользователь MUST иметь возможность менять выбор и видеть счётчик. Выгрузки MUST содержать только текущую выборку в исходном порядке.

#### Scenario: Export a subset
- **WHEN** пользователь выбирает второй и четвёртый форматы, а затем снимает выбор со второго
- **THEN** счётчик показывает одну запись и обе выгрузки включают только четвёртый формат

#### Scenario: Empty selection
- **WHEN** не выбран ни один формат
- **THEN** кнопки копирования недоступны и буфер обмена не изменяется

#### Scenario: Automatically select a manually edited candidate
- **WHEN** пользователь меняет поле, добавляет или удаляет тег либо переносит значение из находки
- **THEN** карточка выбрана, счётчик и выгрузки обновлены; после ручного снятия галочки следующая правка снова выбирает карточку
- **AND** фокус, сворачивание и переход к редактору обновления сами по себе не меняют выбор; явная кнопка добавления выбирает создание

### Requirement: Display source and supplied similarities
Карточка MUST показывать источник и необязательные совпадения, переданные агентом: существующий id, название, описание и объяснение сходства. Подсказки MUST быть доступны без сети и не менять выбор пользователя. Отсутствие подсказок MUST NOT выдаваться за подтверждённое отсутствие дублей.

#### Scenario: Inspect a possible duplicate
- **WHEN** для кандидата переданы два похожих формата
- **THEN** пользователь может прочитать оба описания и объяснения, продолжить редактирование и независимо выбрать или пропустить кандидата

#### Scenario: Similarities were not supplied
- **WHEN** агент не передал похожие форматы или передал пустой список
- **THEN** интерфейс скрывает пустой блок совпадений, не утверждая, что проверка дублей успешно пройдена

### Requirement: Copy spreadsheet rows in the catalog column order
Кнопка табличного копирования MUST явно обозначать, что копирует только выбранные новые форматы, без заголовка в порядке A–L с пустым id и видео в последней колонке. Булевы значения MUST экспортироваться как TRUE/FALSE, неизвестные как пустые ячейки, списки как значения через запятую. Спецсимволы MUST сохранять границы ячеек, а текст MUST NOT становиться формулой при вставке.

#### Scenario: Paste selected new formats
- **WHEN** пользователь копирует два выбранных формата для таблицы
- **THEN** подготовлены две строки по 12 ячеек: id, название, описание, модератор, зритель на сцене, реквизит, мебель, дополнительно, форма, особенности, подборки, видео
- **AND** обе ячейки id пусты, а id похожих существующих форматов не попадают в новые строки

#### Scenario: Preserve complex text during spreadsheet transfer
- **WHEN** описание содержит кавычки, табуляцию и перенос строки, а текстовое поле начинается со знака формулы
- **THEN** вставка в поддерживаемую таблицу сохраняет одну запись и правильные колонки, а текстовое поле интерпретируется как текст

### Requirement: Copy edited selections for an agent
Кнопка «Скопировать для агента» MUST готовить JSON по документированной версионированной схеме. Он MUST включать идентификатор партии, выбранных кандидатов с текущими полями, их внутренние идентификаторы, источники и переданные совпадения. Значения признаков и списков MUST сохранять типы; постоянные id новых форматов MUST NOT назначаться.

#### Scenario: Return edited candidates to the agent
- **WHEN** пользователь изменил название, описание и неизвестный признак выбранного формата и копирует результат для агента
- **THEN** JSON содержит новые значения и исходные сведения об источнике и совпадениях, не содержит невыбранных кандидатов и не объявляет записи добавленными в таблицу

### Requirement: Validate selected records before copying
Выгружаемый формат MUST иметь непустое название. Агентское копирование MUST проверять всю выборку, табличное — только выбранные новые форматы. Ошибка MUST указываться у поля без изменения буфера. Невыбранная запись и обновление, исключённое из TSV, MUST NOT препятствовать копированию остальных новых строк.

#### Scenario: Fix an empty title
- **WHEN** пользователь очищает название выбранного формата и нажимает кнопку копирования
- **THEN** интерфейс указывает на пустое название и не сообщает об успешном копировании
- **AND** после исправления названия копирование становится доступно

### Requirement: Provide an honest clipboard fallback
Инструмент MUST сообщать об успехе только после подтверждённого копирования. При недоступном или отклонённом доступе к буферу MUST оставаться возможность вручную скопировать подготовленную выгрузку из доступного текстового поля без потери правок и выбора.

#### Scenario: Clipboard access is denied for a local file
- **WHEN** браузер отклоняет автоматическое копирование
- **THEN** пользователь получает объяснение и текст выбранной выгрузки для ручного копирования, а редактор сохраняет текущее состояние

### Requirement: Treat supplied content as text
Названия, описания, источники и объяснения совпадений MUST отображаться как текст. Встроенные данные MUST NOT изменять структуру HTML или выполнять код. Ссылки MUST быть активными только для разрешённых HTTP/HTTPS-адресов; остальные значения доступны как текст.

#### Scenario: Source contains markup and a script terminator
- **WHEN** входное описание содержит HTML, закрывающий тег script и обработчики событий, а ссылка имеет схему javascript
- **THEN** текст отображается буквально, код не выполняется, опасная ссылка неактивна и остальные кандидаты остаются доступны

### Requirement: Keep review usable on keyboard and mobile
Выбор, редактирование и обе операции копирования MUST быть доступны с клавиатуры с видимым фокусом и подписями полей. На мобильном экране MUST быть доступны все поля, подсказки и кнопки без горизонтальной прокрутки страницы.

#### Scenario: Review using only a keyboard
- **WHEN** пользователь перемещается клавишей Tab, выбирает запись и редактирует её поля
- **THEN** порядок фокуса позволяет дойти до обеих кнопок копирования и выгрузить выбранное без мыши

#### Scenario: Open on a narrow screen
- **WHEN** ширина экрана составляет 390 пикселей
- **THEN** карточки, поля и совпадения читаемы, а кнопки доступны без горизонтальной прокрутки страницы

### Requirement: Keep review separate from publication
Инструмент MUST работать с подготовленными данными без подключения к Google Sheets, Telegram или сервису ИИ. Генерация MUST NOT помещать партии в public или dist проекта. Выбор и копирование MUST NOT запускать запись в таблицу, назначение постоянных id или Publish.

#### Scenario: Prepare a batch without credentials
- **WHEN** агент запускает генератор с корректным входным файлом без ключей Google и доступа к Telegram
- **THEN** HTML создаётся локально вне публичных каталогов, а данные каталога и таблицы не изменяются

### Requirement: Select existing classification values and create new tags
Для формы, особенностей и подборок редактор MUST предлагать существующие значения из подготовленного снимка каталога или переданных вариантов и кандидатов. Пользователь MUST иметь возможность выбрать несколько значений, удалить выбранное и явно создать новый тег. Новый тег MUST быть доступен другим карточкам той же группы. HTML MUST работать без сети.

#### Scenario: Choose existing values and remove a tag
- **WHEN** пользователь выбирает существующие теги и удаляет один из выбранных
- **THEN** обе выгрузки содержат только оставшиеся значения в соответствующей группе

#### Scenario: Create a tag for the batch
- **WHEN** пользователь выбирает «Новый тег…» и подтверждает непустое значение
- **THEN** тег добавлен текущему формату и доступен для выбора в той же группе у остальных кандидатов

#### Scenario: Populate choices without embedding the catalog
- **WHEN** генератор получает снимок существующего каталога версии 2 или 3
- **THEN** в автономный HTML встраиваются варианты классификации без остальных записей снимка

### Requirement: Select or clear the whole batch
Пользователь MUST иметь возможность выделить все видимые форматы или убрать их выделения одним действием. При фильтрации массовый выбор MUST затрагивать только текущую категорию, сохранять скрытые решения и правки, включать свёрнутые карточки и обновлять общий счётчик выгрузки.

#### Scenario: Select and clear edited candidates
- **WHEN** пользователь правит поля, выделяет все форматы, а затем убирает все выделения
- **THEN** все галочки сняты, копирование недоступно, а правки остаются в карточках

### Requirement: Collapse cards independently of review state
Пользователь MUST иметь возможность сворачивать и разворачивать карточки по одной и все видимые сразу. Название и галочка MUST оставаться доступны в свёрнутом виде. Правки и выбор MUST сохраняться; выгрузки MUST включать выбранные записи независимо от раскрытия и фильтра.

#### Scenario: Export collapsed records and resume editing
- **WHEN** пользователь сворачивает отредактированные выбранные карточки и копирует результат
- **THEN** выгрузка содержит текущие значения, а после раскрытия полей видны сохранённые правки

### Requirement: Distinguish incoming and existing descriptions
Развёрнутая карточка MUST начинаться с единого блока названия и описания импортируемого формата. Сразу за ним MUST идти похожие записи каталога без промежуточного блока исходного текста. Первый или рекомендованный похожий формат MUST показывать название и полное описание сразу; причина сходства MUST быть подписана отдельно.

#### Scenario: Compare a candidate to the catalog
- **WHEN** у кандидата передано совпадение
- **THEN** пользователь видит находку и действие, может раскрыть полный снимок «В каталоге» с причиной совпадения и сравнить описания

### Requirement: Show a complete existing-format snapshot and its link
У каждого совпадения MUST быть ссылка и полный снимок: название и описание видны в самом блоке, а id, признаки, мебель, классификации, дополнительно и видео доступны через «Параметры и ссылки». Дополнительные поля MUST использовать группы редактора; значения MUST показываться обычным текстом без оформления полей ввода. Отсутствующие данные старого снимка MUST обозначаться «Не передано», а не отрицательными значениями.

#### Scenario: Review a full match while editing
- **WHEN** пользователь меняет признаки, теги или видео черновика
- **THEN** редактор сравнения обновляет итог, поля существующего снимка сохраняются, а HTTP(S)-ссылка позволяет открыть формат

### Requirement: Collapse each similar format independently
Рекомендованная цель MUST показываться первой и раскрытой; без цели раскрывается первое совпадение. Остальные похожие форматы MUST начинаться свёрнутыми с видимым названием. Раскрытие MUST давать полный текст и действия без сокращения данных. Раскрытие одного совпадения MUST NOT раскрывать остальные, менять выбор или терять правки.

#### Scenario: Inspect one of several matches
- **WHEN** пользователь раскрывает первое совпадение и затем сворачивает его
- **THEN** остальные совпадения сохраняют состояние, а выбранная цель и отредактированные поля не меняются

### Requirement: Preserve original source text independently of the draft
Исходный текст MUST сохраняться дословно в партии и JSON-выгрузке отдельно от редактируемого описания. Интерфейс MUST показывать безопасную ссылку на источник при её наличии, без отдельного блока исходного текста. Отличие черновика от исходника само по себе MUST NOT показываться как предупреждение. Поля MUST иметь короткие подписи «Название» и «Описание». HTML MUST NOT сам переписывать исходный текст или дополнять правила.

#### Scenario: Edit the catalog description
- **WHEN** пользователь меняет описание для каталога
- **THEN** исходный текст остаётся прежним, правка сохраняется в черновике без уведомления об отличии текстов

### Requirement: Preserve the video field through review and export
Редактор MUST показывать поле «Видео» и видео существующего совпадения, сохранять обычный текст и многострочные ссылки в JSON и колонке L TSV. HTTP(S)-ссылки MUST быть доступны для открытия без автоматической загрузки. Старые партии без видео MUST открываться с пустым полем.

#### Scenario: Export several video URLs
- **WHEN** пользователь добавляет две ссылки на разных строках
- **THEN** JSON сохраняет текст и перенос строки, а TSV помещает обе ссылки в одну ячейку колонки L

### Requirement: Explicitly update a chosen existing format
Пользователь MUST иметь возможность выбрать «Обновить этот формат» у полного снимка совпадения. Редактор MUST заполняться текущими полями цели, сохранять её постоянный id и явно показывать режим обновления. Неполный снимок MUST NOT подменяться пустыми значениями для обновления. Выбор режима MUST NOT автоматически ставить галочку.

#### Scenario: Start an update from existing values
- **WHEN** пользователь выбирает существующий формат для обновления
- **THEN** редактор содержит его текущие значения, включая признаки и видео, и показывает выбранную цель

### Requirement: Preserve drafts when switching review actions
Черновики нового формата и обновления каждой цели MUST сохраняться независимо, включая повторное открытие в том же браузере. Возврат к созданию, повторный выбор той же цели или переход к другому совпадению MUST NOT сбрасывать внесённые правки или менять исходный снимок.

#### Scenario: Switch between creation and two update targets
- **WHEN** пользователь правит новый формат, обновляет два разных совпадения и возвращается к каждому режиму
- **THEN** соответствующие названия и поля восстанавливаются из отдельных черновиков

### Requirement: Export update patches separately from new rows
Агентская выгрузка версии 2 MUST различать create и update. Обновление MUST содержать targetId и только изменённые поля со значениями before/after, сохраняя типы. TSV MUST исключать обновления. Пустое обновление и несколько выбранных обновлений одного id MUST блокировать агентское копирование с объяснением.

#### Scenario: Export a mixed selection
- **WHEN** выбраны новый формат и обновление существующего
- **THEN** JSON содержит обе операции с явными типами, а TSV только новую строку

#### Scenario: Select updates only
- **WHEN** в выборке только обновления
- **THEN** табличная кнопка недоступна, а после внесения правок агентская выгрузка содержит целевые id и before/after

### Requirement: Keep finding fields visible during updates
В показанных строках обновления инструмент MUST показывать сохранённые поля находки с правками пользователя и позволять переносить их по одному; полный набор MUST раскрываться по запросу. Перенос MUST сохранять остальные поля, находку и исходный снимок цели. Результат MUST оставаться редактируемым и передаваться агенту как before/after.

#### Scenario: Replace one field and retain the finding
- **WHEN** пользователь нажимает «Заменить» у описания находки и затем правит итог
- **THEN** изменено только описание выбранной цели, находка остаётся видимой и неизменной, а переключение режимов сохраняет оба черновика

### Requirement: Add or replace finding values explicitly
Видео MUST дополнять текущий текст отсутствующими непустыми строками, а классификации MUST дополнять текущие массивы отсутствующими тегами. Описание, название, признаки, мебель и заметка MUST заменяться только по явному действию. Повторный перенос MUST NOT добавлять повторы.

#### Scenario: Add finding videos and tags to an existing format
- **WHEN** пользователь нажимает «Добавить» у видео и тегов находки
- **THEN** итог сохраняет прежние видео и теги и добавляет только отсутствующие значения, а остальные поля не меняются

### Requirement: Display agent recommendations with consistent action markers
Необязательная рекомендация MUST содержать действие и краткую причину. Карточки MUST использовать единые метки: ➕ добавить, 🔄 обновить, 🟰 дубль, ⏭️ пропустить, ❓ проверить. Общая легенда MUST NOT показываться. Рекомендации MUST показываться без префикса «Агент:», причины совпадения — с подписью «Сходство:». Дубль MUST быть отмечен цветной меткой, доступной также при сворачивании. Рекомендация MUST сохраняться как контекст при ручном изменении решения.

#### Scenario: Inspect a recommended duplicate
- **WHEN** агент нашёл существующий формат без полезных дополнений
- **THEN** карточка явно помечена дублем и не выбрана, причина и существующая запись доступны для просмотра

#### Scenario: Sort the review list by recommendation
- **WHEN** пользователь открывает подборку
- **THEN** карточки расположены в порядке create, update, review, skip, duplicate; отсутствие рекомендации считается review, внутри групп сохраняется исходный порядок
- **AND** правки и смена режима не перемещают карточки, а порядок выгрузок остаётся исходным

### Requirement: Show differing values and the source of the result
Редактор обновления MUST выделять цветом и текстовой отметкой строки с различающимися значениями. Источники итогового значения MUST быть выделены без дублирующих меток над итогом. Метки предложения и ручной правки MUST показываться только для итога, отличного от обоих источников и их объединения. Возврат поля из каталога MUST сохранять остальные поля. Подсветка MUST NOT менять выгрузку: экспортируются только отличия итога от каталога.

#### Scenario: Choose a value and restore the catalog version
- **WHEN** пользователь берёт название из находки, редактирует его и возвращает значение каталога
- **THEN** подсветка показывает находку, затем появляется метка ручной правки, затем подсвечивается каталог; после возврата название не входит в обновление, а другие правки сохраняются

#### Scenario: Equal values stay visually quiet
- **WHEN** находка, каталог и итог поля совпадают
- **THEN** подсвечены оба источника, кнопки переноса и метки происхождения скрыты; после ручного изменения итога появляются отметка отличия и действия возврата, а возврат исходного значения снова скрывает их

### Requirement: Keep the chosen update target beside the finding
Кнопка «Подготовить обновление» MUST открывать локальный черновик выбранной записи без записи в каталог. При выборе цели она MUST раскрываться первой непосредственно под находкой, остальные совпадения MUST сворачиваться. Редактор полей MUST идти после блока совпадений. Повторное нажатие MUST сохранять правки и снова сворачивать остальные совпадения. Чтение других совпадений MUST оставаться доступным без смены цели.

#### Scenario: Choose another match for an update
- **WHEN** пользователь раскрывает два совпадения и выбирает второе для обновления
- **THEN** второе совпадение становится первым под находкой, прежнее сворачивается, редактор ниже показывает черновик новой цели, прежние правки сохраняются отдельно

### Requirement: Start recommended updates without losing catalog data
Рекомендованное обновление MUST указывать существующую цель и непустые реальные изменения. Редактор MUST начинаться со снимка каталога и менять только указанные поля, сохраняя видимую находку. Рекомендация MUST NOT заменять заполненное поле пустым, неизвестным значением или удалять прежние видео и теги. Менее полная находка сама по себе MUST NOT считаться обновлением.

#### Scenario: Open a prepared update
- **WHEN** рекомендация дополняет видео и заметку выбранной цели
- **THEN** редактор содержит предложенные значения и прежние остальные поля, карточка выбрана, JSON содержит update, а TSV её исключает

#### Scenario: Reject an update that clears known data
- **WHEN** рекомендованные изменения заменяют заполненный признак null или удаляют прежнее видео
- **THEN** генератор отклоняет рекомендацию с указанием поля без перезаписи HTML

### Requirement: Review updates through a unified field editor
В обновлении MUST быть единые строки с находкой, каталогом и редактируемым итогом. Изначально MUST показываться отличия находки от каталога и изменённые поля итога; все поля MUST раскрываться по запросу. Просмотр отличий MUST NOT менять итог, выбор или выгрузку. Правки и черновики целей MUST сохраняться при переключении представления. Только что отредактированное поле MUST NOT исчезать при возврате к исходному значению.

#### Scenario: Review only proposed changes and expand the full format
- **WHEN** пользователь раскрывает рекомендованное обновление видео и затем выбирает все поля
- **THEN** сначала видны видео и поля с отличиями находки от каталога, затем доступны все поля без потери правок и выбора

#### Scenario: Prepare an update before editing any values
- **WHEN** пользователь нажимает «Подготовить обновление» для записи, отличающейся от находки
- **THEN** сразу видны различающиеся поля, итог содержит значения каталога, счётчик изменений равен нулю, галочка не меняется; сообщение о совпадении появляется только при отсутствии всех отличий

### Requirement: Group fields consistently across review modes
Редакторы создания и обновления MUST использовать группы «Основное», «Требования», «Классификация», «Заметки и видео». В снимке каталога название и описание MUST показываться отдельно от раскрываемых дополнительных групп. При обновлении группы MUST быть визуально разделены и сохранять три колонки на широком экране. Группа без видимых полей MUST скрываться. Комментарий агента к совпадению MUST кратко объяснять решающее сходство, дополнение или различие без пересказа описаний.

#### Scenario: Show only groups with changes and reveal the complete format
- **WHEN** в обновлении меняется только видео и пользователь затем показывает все поля
- **THEN** сначала видна только группа заметок и видео, затем раскрываются все группы; правки, находка и снимок сохраняются

### Requirement: Start from a compact review list
Карточки MUST начинаться свёрнутыми с галочкой, названием, рекомендацией и краткой причиной. Название и стрелка MUST раскрывать карточку. «Редактировать» MUST открывать форму вместо превью, «Готово» — возвращать превью. Обновление MUST сразу показывать изменяемые поля. Решение MUST быть видно отдельно от рекомендации. Без совпадений MUST NOT быть пустой панели каталога.

#### Scenario: Inspect a duplicate and start editing it
- **WHEN** пользователь раскрывает дубль и затем открывает его поля
- **THEN** сначала видны объяснение, описание и доступ к существующему формату, затем появляется редактор; изменения автоматически выбирают карточку

### Requirement: Filter categories without changing the selection
Категории рекомендаций MUST быть доступны как кнопки со счётчиками и явным активным состоянием. Фильтрация MUST сохранять правки, раскрытие и выбор. Выгрузки MUST включать все выбранные записи, включая скрытые фильтром. При ошибке пустого названия скрытой выбранной записи интерфейс MUST снять фильтр, раскрыть редактор и сфокусировать ошибочное поле.

#### Scenario: Export selections from multiple categories
- **WHEN** пользователь выбирает записи в разных категориях и копирует результат из категории дублей
- **THEN** выгружаются все выбранные записи в исходном порядке партии с последними правками, общий счётчик разделяет новые записи и обновления

### Requirement: Make creation an explicit decision
Кнопки «Добавить» и «Добавить как новый» MUST выбирать создание записи для выгрузки. «Снять выбор» MUST исключать операцию, сохраняя черновики. Основной кнопкой выгрузки MUST быть «Скопировать для агента»; копирование только новых строк MUST оставаться отдельным действием.

#### Scenario: Add a preview without editing
- **WHEN** пользователь нажимает «Добавить» в превью находки без открытия редактора
- **THEN** карточка выбирается, редактор не требуется, а текущее решение видно рядом с действиями

### Requirement: Toggle the hovered card with keyboard shortcuts
Без модификаторов физическая C MUST переключать раскрытие карточки под курсором, S — её выбор. При вводе в поле, селекторе, contenteditable, во время IME, в диалоге ручного копирования и при автоповторе действие MUST NOT выполняться. Клавиши MUST работать в русской раскладке и использовать текущую позицию курсора. Сворачивание MUST NOT оставлять фокус в скрытом теле.

#### Scenario: Toggle the hovered card and retain its draft
- **WHEN** пользователь наводит курсор на карточку и нажимает C и S
- **THEN** раскрытие и выбор переключаются только у неё, счётчик и выгрузки обновляются, правки сохраняются

#### Scenario: Keep typing and application shortcuts intact
- **WHEN** фокус находится в поле либо пользователь нажимает сочетание с модификатором
- **THEN** карточки не переключаются и обработчик не перехватывает действие

### Requirement: Prefill requirements from the described mechanics
Агент MUST выводить требования из правил, включая отрицательные значения, когда механика явно обходится без модератора, зрителя на сцене, реквизита или мебели. Неоднозначные требования MUST оставаться неизвестными. Генератор MUST NOT заменять null отрицательным значением автоматически; заполненные поля каталога MUST сохранять приоритет.

#### Scenario: Infer requirements for an emotion scene
- **WHEN** четыре актёра играют сцену с закреплёнными эмоциями без дополнительных участников или оборудования
- **THEN** агент предзаполняет moderator, audienceOnStage и props как false, furniture как «Нет»

### Requirement: Exclude overall duration from proposed notes
Агент MUST NOT добавлять общую продолжительность формата или раунда в note новой записи или предлагаемого обновления. Тайминги, определяющие механику игры, MUST сохраняться в правилах. Исходный текст и снимки каталога MUST оставаться неизменными.

#### Scenario: Import a season-specific duration
- **WHEN** источник задаёт четырёхминутный раунд и повтор сцены за уменьшающиеся интервалы
- **THEN** общая продолжительность не переносится в note, интервалы повтора сохраняются в описании, источник не меняется

### Requirement: Resize the review panels
Максимальная ширина по умолчанию MUST быть 1054 px, на 15% меньше прежних 1240 px. Правый край MUST позволять перетаскивание и изменение клавиатурой в пределах экрана. Ширина MUST сохраняться при доступном хранилище; его недоступность MUST NOT мешать работе. Изменение ширины MUST NOT терять правки, выбор или раскрытие карточек.

#### Scenario: Resize an edited review and reopen it
- **WHEN** пользователь перетаскивает край панели с отредактированной карточкой и перезагружает страницу
- **THEN** при изменении ширины черновик и выбор сохраняются, а после перезагрузки восстанавливаются ширина, правки, выбор и раскрытие карточки

### Requirement: Autosave review work locally
Редактор MUST сохранять поля, выбор, черновики каждой цели, новые теги, метки ручных правок и состояние просмотра после изменения. Повторное открытие в том же браузере MUST восстанавливать сохранённое состояние до редактирования. Сохранение MUST быть изолировано по подборке и проверяться относительно её исходных кандидатов. Статус MUST явно сообщать об успешном сохранении или ошибке.

#### Scenario: Reopen selected and unselected work
- **WHEN** пользователь меняет несколько черновиков, снимает выбор с одного и закрывает страницу
- **THEN** при повторном открытии восстанавливаются все правки и точный выбор; переключение между созданием и целями обновления сохраняет каждый черновик

#### Scenario: Storage cannot accept an edit
- **WHEN** хранилище недоступно или запись завершилась ошибкой
- **THEN** правка остаётся на странице, предыдущее сохранение сохраняется, показана ошибка и доступно копирование результата

#### Scenario: Saved data is incompatible or changed elsewhere
- **WHEN** сохранение повреждено, исходные кандидаты изменились или другая вкладка записала более новое состояние
- **THEN** несовместимое состояние не применяется и не перезаписывается молча; пользователь видит причину и может явно сбросить сохранение

### Requirement: Reset to the original review
«Сбросить правки» MUST запрашивать подтверждение и возвращать поля, все черновики и выбор текущей подборки к исходному состоянию. Сохранение текущей подборки MUST удаляться, остальные подборки и ширина MUST сохраняться. Отмена MUST оставлять правки без изменений. Ошибка удаления MUST сохранять текущую работу и явно сообщать, что сброс не выполнен.

#### Scenario: Confirm or cancel a reset
- **WHEN** пользователь отменяет сброс, затем подтверждает его и перезагружает страницу
- **THEN** отмена сохраняет работу, подтверждение восстанавливает исходные поля и рекомендованный выбор, старые правки не возвращаются

### Requirement: Reset one format independently
После подтверждения «↺ Сбросить» MUST восстанавливаться исходные поля, рекомендация, начальный выбор и все черновики только этого кандидата. Карточка MUST оставаться раскрытой. Остальные кандидаты, общие варианты тегов и категория MUST сохраняться. Результат MUST сохраняться через обычное автосохранение с теми же правилами ошибок и конфликтов. Отмена и Escape MUST оставлять работу без изменений и возвращать фокус к кнопке карточки.

#### Scenario: Reset a format with several action drafts
- **WHEN** пользователь меняет создание и несколько целей обновления одного формата, подтверждает его сброс и перезагружает страницу
- **THEN** восстанавливаются исходные поля и начальный выбор этого формата, старые черновики не возвращаются, а остальные карточки сохраняют правки и выбор

### Requirement: Show individual reset only for edited fields
Раскрытая карточка MUST показывать «↺ Сбросить» только при отличии полей от начальных значений хотя бы в одном её черновике. Галочка выбора, переключение режима и исходное предложение агента MUST NOT считаться правками. Ручной возврат всех полей к начальным значениям и сброс MUST скрывать кнопку. После подтверждённого сброса фокус MUST возвращаться к названию карточки.

#### Scenario: Undo field edits without undoing selection
- **WHEN** пользователь меняет поле, выбирает формат и вручную возвращает поле к исходному значению
- **THEN** кнопка появляется после правки и исчезает после её отмены, хотя формат остаётся выбранным

#### Scenario: Reopen a format with an edited inactive draft
- **WHEN** пользователь меняет один черновик, переключается на другой без правок и перезагружает страницу
- **THEN** кнопка остаётся доступной при раскрытии карточки, поскольку другой черновик содержит правки
