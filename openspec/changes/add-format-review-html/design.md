# Design

## Context

Мотивация и согласованный объём описаны в `proposal.md`. Сейчас браузерная модель в `src/types.ts` содержит постоянный `id` и вычисляемые поля `searchText`/`furnitureKinds`; новые кандидаты ещё не являются такими записями. Порядок A–L определён в `scripts/lib/published-catalog.mjs` и Apps Script, который выдаёт постоянный id при Publish.

В проекте уже есть Node-скрипты на ES modules, Vitest и Playwright с широким и мобильным экранами. Обычная сборка публикует `public/`, а `ignore/` исключён из Git и закрыт для Vite. Это позволяет сделать отдельный локальный инструмент без изменения сайта и доступа к Google.

Дизайн нужен для фиксации новой схемы кандидатов, автономного выполнения и двух совместимых способов передачи результата.

## Goals / Non-Goals

**Goals:**

- Повторяемая генерация одного HTML из данных партии с одинаковым интерфейсом.
- Общие правила проверки и экспорта, пригодные для Node и браузера без копирования логики.
- Простой контракт данных, который агент может заполнить вручную или программно.

**Non-Goals:**

- Автосохранение и восстановление между открытиями: правки и выбор живут в памяти открытой страницы, результат пользователь передаёт кнопками копирования.
- Выполнение сбора и поиска дублей внутри HTML. Сведения о сходстве являются входными данными, а не результатом работы инструмента.
- Автоматическая запись в Google-таблицу из HTML и автоматическое слияние описаний. Обновления готовятся как отдельные задания агенту по явному выбору пользователя.
- Приём заявок с сайта, включая предложения видео; для них не вводятся статусы, сервер или отдельные типы предложений. Поле «Видео» является частью редактируемой записи.

## Decisions

### 1. Постоянный шаблон и генератор JSON → HTML

Добавить шаблон, стили и небольшой браузерный контроллер в `tools/format-review/`, чистую модель/сериализаторы в `scripts/lib/format-review.mjs`, генератор в `scripts/generate-format-review.mjs`. Команда `npm run review:generate -- --input <batch.json> --output <review.html>` создаёт готовую партию. Если выходной путь опущен, используется `ignore/format-review/review.html`.

Генератор сначала целиком читает и проверяет JSON, затем встраивает данные, стили и код в один HTML. Общая модель встраивается в тот же inline-модуль, что и контроллер, без внешних импортов, fetch и сборки публичного сайта. Все файлы инструмента остаются вне `public/`; явный выходной путь в `public/` или `dist/` проекта отклоняется с учётом символических ссылок. Для записи используется временный файл с последующим переименованием, чтобы не оставлять частичный результат.

Альтернативы: генерировать новый интерфейс агентом каждый раз — поведение расходится между партиями; внешний JSON рядом с HTML — чтение файлов через браузер потребовало бы дополнительного действия или сервера; отдельное приложение с сервером — лишний этап запуска для одного файла.

### 2. Небольшая отдельная модель партии

Вход имеет `schemaVersion: 1`, `kind: "format-review-batch"`, непустой `batchId`, необязательный заголовок `title` и массив `candidates`. Пустой массив допустим. Необязательный `classificationOptions` содержит три массива `forms`, `features`, `collections` с вариантами из существующего каталога. Каждый кандидат содержит:

| Поле | Содержание |
| --- | --- |
| `candidateId` | Непустой уникальный идентификатор внутри партии; не является id каталога |
| `format` | `title`, `description`, `moderator`, `audienceOnStage`, `props`, `furniture`, `note`, `forms`, `features`, `collections`, `video` |
| `source` | Обязательная подпись `label`, необязательные `url` и исходный `text` |
| `similarFormats` | Снимки: обязательны `id`, `title`, `description`, `reason`; для полного сравнения передаются остальные поля формата и необязательный `url` |

Текстовые поля формата имеют тип string; признаки — boolean/null; три классификации — массивы непустых строк. Схема не содержит постоянного id нового формата или вычисляемых браузерных полей. Агент выводит требования по механике, ставя false и мебель «Нет», когда они явно не нужны; неоднозначные признаки задаёт как null, неизвестные текст и списки — пустой строкой и пустым массивом. Генератор не делает смысловых выводов. Общая продолжительность не переносится в note, а тайминги самой механики сохраняются в правилах. Исходники и снимки не меняются. Отсутствие обязательного поля, неверный тип, неподдерживаемая версия и повтор `candidateId` дают ошибку с путём к полю до записи HTML.

Альтернатива — повторно использовать `FormatRecord` или парсер опубликованного каталога — потребовала бы выдумывать id и вычисляемые поля для ещё не принятых записей. Отдельная модель сохраняет границу между кандидатом и каталогом.

### 3. Компактные карточки и редактор изменений

Карточки начинаются свёрнутыми. В заголовке — название находки, короткая причина рекомендации, её метка и галочка. При раскрытии краткая причина из заголовка скрывается, краткое объяснение с подписью «Агент:» показывается один раз в блоке действия; каждое совпадение изначально свёрнуто и показывает название с двумя строками описания; при раскрытии доступны полные данные и короткий вывод агента. Раскрытие совпадений независимо и не сбрасывается при смене режима или сворачивании родительской карточки. Название редактируется в форме; при обновлении заголовок сохраняет имя находки и не подменяет его именем цели.

Тело занимает всю ширину. Источник раскрывается дословно; отдельный раскрываемый блок содержит полные снимки совпадений с описанием, постоянным id, всеми полями, ссылкой и причиной сходства. В нём доступны выбор и смена цели. Без совпадений пустой боковой колонки нет.

Новая запись имеет обычный редактор. Дубль или пропуск сначала показывают краткое описание и кнопку открытия полей находки. В обновлении редактор состоит из единых строк «Находка / В каталоге / Итог» с переносом значений по полю. Изначально видны реальные изменения, все поля раскрываются кнопкой. Поля, затронутые ручной правкой, остаются видимыми до явного возврата к краткому виду, чтобы отмена изменения не убирала активный контрол. Длинные редактируемые тексты увеличивают высоту в разумных пределах.

Классификации допускают выбор существующих тегов, удаление и создание нового значения. Новые теги становятся доступны в своей группе. Видео — обычный текст с безопасными HTTP(S)-ссылками. Отсутствующие поля прежнего снимка обозначаются «Не передано», null остаётся неизвестным, false — отрицательным.

Начальный выбор следует рекомендации; без неё он пуст. Ручная правка или перенос выбирают карточку автоматически. Программное восстановление при смене режима, фокус и сворачивание выбор не меняют. Данные, черновики создания и целей, состояние источника и выбор сохраняются при переключении вида. Ошибка копирования раскрывает скрытое обязательное поле перед фокусировкой.

Основная компоновка и визуальная проверка ориентированы на десктоп. Сохраняются массовое управление, доступность с клавиатуры и обе выгрузки. Состояние хранится по candidateId; представление сортируется отдельно от исходной партии.

### 4. Две выгрузки одной выборки

Агентская выгрузка проверяет всех выбранных кандидатов, табличная — только выбранные новые записи. Пустая выборка отключает соответствующую кнопку; ошибка в записи, которая не попадает в эту выгрузку, её не блокирует. Порядок исходной партии сохраняется.

«Скопировать новые для таблицы (N)» сериализует только новые записи в TSV без заголовка и с 12 колонками: пустой id, название, описание, модератор, зритель на сцене, реквизит, мебель, дополнительно, форма, особенности, подборки, видео. При отсутствии выбранных новых форматов кнопка недоступна. Признаки дают TRUE/FALSE/пусто, классификации соединяются через `, `. Кавычки удваиваются, ячейки с табуляцией, кавычкой или переносом строки заключаются в кавычки. Текст, который табличный редактор мог бы трактовать как формулу, получает транспортное экранирование апострофом; исходный черновик от этого не меняется.

«Скопировать для агента» выдаёт JSON с `schemaVersion: 2`, `kind: "format-review-selection"`, `batchId` и выбранными `candidates`. У каждого элемента есть явный `action`: `create` содержит текущий `format`, `update` содержит `targetId`, `targetTitle` и только изменённые поля `changes` со значениями `before`/`after`. У обновления нет `format`, поэтому оно не выглядит новой строкой. Источник и снимки совпадений сохраняются; текст, null и массивы передаются без табличного экранирования. Это решение пользователя, а не подтверждение записи в таблицу.

### 4.1. Режим обновления и независимые черновики

Кнопка «Обновить этот формат» выбирает одно совпадение и заполняет редактор его полным текущим снимком, включая видео. Неполный снимок или некорректный id не допускают обновления. Галочка выбора не меняется автоматически. Единая строка действия показывает цель и количество изменённых полей; редактор сначала показывает только изменяемые поля.

Для каждой карточки хранятся отдельные черновики создания и обновления каждого target id. Переключение сохраняет текущий черновик и восстанавливает нужный, не перезаписывая исходные снимки. Постоянный id цели не зависит от редактирования названия. Обновление без изменений и несколько выбранных обновлений одного target id дают понятную ошибку перед копированием. Автоматического объединения таких правок нет.

В режиме обновления каждая показанная строка объединяет сохранённую находку, исходное значение каталога и редактируемый итог с кнопкой переноса. Используется черновик новой записи с правками, сделанными до переключения; исходный текст источника остаётся отдельным дословным текстом. Выбор режима сам ничего из находки не переносит. «Добавить» для видео сохраняет текущий текст и дописывает отсутствующие непустые строки; повторы сравниваются после удаления пробелов по краям строки, без смыслового разбора. Для классификаций сохраняется порядок текущих тегов и добавляются отсутствующие значения. «Заменить» для названия, описания, признаков, мебели и заметки явно заменяет одно поле, включая видимое пустое или неизвестное значение. Перенос не меняет находку, исходный снимок каталога или другие поля. Кнопка недоступна, когда действие не изменит значение; итог можно поправить вручную.

Агент при дальнейшем отдельном поручении на запись обязан прочитать актуальную запись по target id и сверить значения изменяемых полей с `before`. Конфликт требует разбора; при совпадении меняются только перечисленные поля на `after`, остальные поля и id сохраняются. Реализация записи не входит в HTML-инструмент.

Альтернатива — один текстовый формат для обоих адресатов — либо теряет источники и совпадения при возврате агенту, либо не подходит для вставки в таблицу.

### 5. Копирование с доступным ручным способом

По нажатию используется Clipboard API; успех показывается только после завершения операции. Если API отсутствует или браузер отклоняет запрос, раскрывается подписанное read-only поле с точно той же выгрузкой, выделением текста и инструкцией скопировать вручную. Достаточно этого резервного способа; добавлять зависимость от устаревших методов копирования не требуется.

Текст для ручного копирования доступен и для проверки сложной табличной выгрузки. Браузерные проверки моделируют успех и отказ, а реальный локальный файл проверяется отдельно: тестовый HTTP-сервер не доказывает работу `file://`.

### 6. Данные остаются текстом

Встроенный JSON экранируется так, чтобы `</script>` и другие HTML-последовательности не могли закрыть контейнер данных. Интерфейс заполняет текстовые узлы и значения контролов без вставки данных в HTML-разметку. URL активируется только после проверки схемы HTTP/HTTPS; внешние ресурсы не подгружаются автоматически. Вымышленный пример можно коммитить, реальные партии и HTML сохраняются в `ignore/` либо другом непубличном месте.

Альтернатива — подстановка исходного текста непосредственно в разметку — нарушает контракт обычного текста и может сломать весь файл одной записью.

### 7. Скилл для двух стадий работы агента

`import-formats` хранится в `.agents/skills/` проекта и подключается символической ссылкой в личную папку скиллов. Он использует существующие документацию, модель и генератор. Для каждого источника агент готовит отдельные файлы партии, снимка каталога, HTML и состояния в `ignore/format-review/`, затем завершает ответ до получения решения пользователя. При возврате JSON скилл проверяет его относительно исходной партии вспомогательным скриптом, различает создание и обновление и перед разрешёнными изменениями сверяет свежие значения. Проверка не записывает в таблицу; полномочия на запись и публикацию определяются поручением пользователя и действующими инструкциями проекта.

### 8. Рекомендованные действия и начальные черновики

Кандидат может содержать `recommendation`: `action` из create/update/duplicate/skip/review и непустой `reason`. Update также содержит `targetId` и `changes` с конечными значениями только изменяемых полей; duplicate указывает `targetId`. Цель должна быть среди переданных совпадений. Обновление требует полного снимка, реальных изменений и сохранения заполненных значений: пустые, null и сокращённые списки/видео не могут вытеснять известные данные. Смысловую полезность дополнений определяет агент; менее полная находка без новых сведений получает duplicate.

Эмоджи и подписи определены одним справочником модели, используются в метках карточек. Общей легенды и общей подсказки клавиш нет; горячие клавиши сохранены. Create/update изначально выбраны, остальные действия нет. Update начинает отдельный черновик со снимка цели и предложенных полей; исходная находка сохраняется. Пользователь может менять поля, режим и выбор без повторного применения рекомендации. Duplicate окрашивает всю карточку и имеет текстовую подпись; он остаётся доступным для ручного пересмотра. В агентском результате рекомендация — контекст, а фактическое действие задаёт текущий режим пользователя.

Порядок этого справочника также задаёт начальный порядок показа: create → update → review → skip → duplicate. Сортируется копия списка, равные приоритеты сохраняют исходный порядок; без рекомендации используется review. Нумерация соответствует экрану. Исходная партия и порядок выгрузок не меняются, редактирование не вызывает повторную сортировку.

### 9. Горячие клавиши и ширина

Физические C/S действуют на карточку под текущей позицией курсора, включая русскую раскладку; фокус в текстовом поле, селекторе или contenteditable, модификаторы, IME, автоповтор и ручной диалог блокируют обработку. При сворачивании фокус из скрываемого тела переносится на стрелку.

Общий контейнер шапки, карточек и нижней панели ограничен 1054 px по умолчанию. Правый край меняет ширину симметрично относительно центра через pointer capture, стрелки и Home/End доступны с клавиатуры, двойной клик сбрасывает настройку. Границы — от 760 px или доступной ширины меньшего экрана до ширины экрана с полями. Только предпочтение ширины сохраняется в localStorage с обработкой отказа; черновики остаются временными. При изменении ширины видимые textarea подстраивают высоту.

### 10. Общие группы полей

Снимок и оба режима редактора используют один справочник групп: основные поля, требования, классификация, заметки и видео. Снимок показывает значения в неизменяемых полях и метках вместо вертикальной таблицы; id остаётся возле действий. При обновлении параметр сохраняет три колонки, а фон и рамка отделяют группы. После обновления строк скрываются группы без видимых полей; перенос, черновики и выгрузки используют прежнюю модель. Комментарии к совпадениям содержат одну короткую мысль без пересказа описаний.

### 11. Краткие признаки дубля

Видимые метки содержат только подпись и символ: зелёный ✓ для совпадения, оранжевый ≠ для различия, нейтральный ? для неполных/неизвестных данных. У параметров рядом с ≠ показано количество известных отличий. Развёрнутые объяснения остаются в title и доступном имени.

Шапка дубля содержит название, описание и параметры сравнения исходной находки с рекомендованной целью. Название и семь требований/классификаций сравниваются детерминированно с нормализацией пробелов, регистра и порядка тегов; пустые значения не подтверждают совпадение. Необязательное `recommendation.descriptionMatch` (equivalent/different/unknown) хранит смысловую оценку агента; точное непустое описание определяется без неё. Прежние партии без оценки показывают «не оценено», а не вывод из одного статуса duplicate. Ручные черновики не меняют это исходное сравнение. Подсказка параметров раскрывает результат по полям.

## Risks / Trade-offs

- [Ограничения буфера у локального файла] → Ручное копирование является обязательным рабочим путём и проверяется в браузере.
- [Различия вставки TSV в Google Sheets и Excel] → Проверить многострочный текст, табуляцию, кавычки и экранирование формул на вымышленной партии в отдельном тестовом документе. При несовместимости скорректировать транспорт до приёмки, сохранив контракт 12 колонок. Не использовать исходную таблицу для проверки.
- [Потеря правок после закрытия или перезагрузки] → Коротко указать, что правки относятся к открытому сеансу и результат нужно скопировать; возобновление не обещается.
- [Ошибочное совпадение или устаревший снимок] → Показать рекомендацию и причину, дать изменить предварительный выбор и режим; запись в таблицу остаётся отдельным поручением.

## Migration Plan

Добавить инструмент, вымышленный пример и инструкцию, выполнить проверки и создать демонстрационный HTML в `ignore/`. Миграции каталога, таблицы, кэша и деплоя не требуется. Откат состоит в удалении локального инструмента и его команды; публичный сайт не зависит от этих файлов.
