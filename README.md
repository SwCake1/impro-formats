# Что сыграем?

Статический каталог импровизационных форматов. При открытии страницы сайт сразу показывает сохранённый каталог и проверяет обновления `data/formats.json` со своего адреса.

## Данные

Снимок содержит 269 форматов на момент переноса. Используются постоянные идентификаторы из первой колонки `id`; переименование формата не меняет его ссылку.

Порядок полей таблицы A–K: `id`, название, описание, модератор, зритель на сцене, реквизит, мебель, дополнительно, **Форма**, **Особенности**, **Подборки**. В каждой из трёх колонок классификации допускается несколько значений через запятую; пустая ячейка означает пустой список. Следующая колонка `Видео` пока не импортируется и не отображается.

Новый JSON содержит `schemaVersion: 3`, дату `generatedAt` и массив `records`. У каждой записи есть `id`, `title`, `description`, `moderator`, `audienceOnStage`, `props`, `furniture`, `note` и независимые массивы `forms`, `features`, `collections`. Пустые признаки сохраняются как `null`. Параметры поиска и мебели вычисляются из текста при загрузке.

Импорт и браузер также поддерживают прежний снимок версии 2 с общим массивом `tags`: JAM, «Импровизация.Команды» и «Иностранные» относятся к подборкам; короткая и длинная форма — к форме. Кэш версии 2 читается и преобразуется в новую структуру. Данные версии 3 берутся строго из своих полей, без распределения по названиям.

Команда `npm run build` использует фиксированный `public/data/formats.json` для действующей публикации GitHub Pages.

Команда `Publish` сохраняет одобренные данные значениями на листе «Опубликовано». Новая сборка `npm run build:published` читает только этот лист через Sheets API, проверяет данные и сохраняет каталог в `dist/data/formats.json`. При ошибках чтения или данных сборка останавливается. Исходный JSON в репозитории остаётся прежним. Изменения рабочих ячеек попадут в сборку только после Publish.

Сайт опубликован на [impro-formats.vercel.app](https://impro-formats.vercel.app/). Проверены каталог из 269 форматов, сжатие Brotli и HTTP-кэш с ETag. Дальнейшие шаги — в [плане](docs/plan.md).

В клиентской сборке нет адреса таблицы или ключей доступа. Готовый JSON каталога доступен посетителям сайта.

## Кэш

Каталог хранится обычным JSON; сжатие при передаче выполняет хостинг. Последний проверенный набор сохраняется в `localStorage` и показывается сразу при следующем открытии. Затем браузер проверяет HTTP-кэш у сервера (`cache: 'no-cache'`). При прежнем ETag используем сохранённые записи без повторного разбора ответа и перерисовки.

Новую версию проверяем перед заменой кэша. При ошибке сети или данных остаётся сохранённый каталог. Если локальное хранилище недоступно или заполнено, сайт продолжает работать без сохранения между открытиями.

## Сборка с опубликованным снимком

Локальные настройки хранятся в `.env.local`, исключённом из Git. Образец — [.env.example](.env.example):

```dotenv
GOOGLE_SHEET_ID=SPREADSHEET_ID
GOOGLE_APPLICATION_CREDENTIALS=/path/to/service-account.json
```

Запуск:

```bash
npm run build:published
```

В [vercel.json](vercel.json) заданы команда `npm run build:published`, каталог `dist` и заголовок `Cache-Control: public, max-age=0, must-revalidate` для JSON. Заголовок разрешает хранить ответ, но требует проверять его свежесть. На опубликованном сайте проверены этот заголовок, ETag и ответ 304 на условный запрос.

В настройках сборки Vercel заданы `GOOGLE_SHEET_ID` и `GOOGLE_SERVICE_ACCOUNT_JSON` с содержимым JSON-ключа вместо локального пути. Эти переменные используются только процессом сборки и не должны иметь префикс `VITE_`.

## Проверка доступа к Google Sheets

Проверить чтение листа «Опубликовано» от имени технического аккаунта:

```bash
npm run check:sheets -- /path/to/service-account.json SPREADSHEET_ID
```

Команда выводит аккаунт и количество форматов. Ключ и токен в журнал не попадают.
Ключ хранится локально и не должен попадать в Git или `public/`.
Доступ к локальной папке `ignore/` через сервер Vite закрыт.

## Фильтры

На широком экране фильтры расположены в компактной боковой панели с регулируемой шириной. Форма, особенности, подборки и условия расположены в отдельных блоках. На телефоне панель раскрывается над списком; кнопка «Показать N форматов» возвращает к результатам.

В форме выбирается одно значение; запись с несколькими формами подходит по любой из них. Все выбранные особенности должны совпасть. В блоке «Подборки» можно выбрать несколько значений — подойдут форматы хотя бы из одной выбранной подборки. Между блоками условия объединяются через «И». Варианты фильтров берутся из данных каталога.

Выбранные ограничения видны над результатами и снимаются по одному. Поиск и фильтры сохраняются в URL, подборки — повторяющимся параметром `collection`. Старые ссылки на JAM, «Импровизация.Команды» и «Иностранные» распознаются как подборки; новые ссылки сохраняют независимость трёх групп.

## GitHub Pages

Старый способ публикации сохраняется до проверки замены на Vercel.

Workflow `.github/workflows/deploy-pages.yml` собирает и публикует `dist` при push в `main`. В настройках отдельного GitHub-репозитория выберите **Settings → Pages → Source → GitHub Actions**.

Проект использует относительный `base`, поэтому работает и на корневом домене, и по адресу вида `username.github.io/repository/`.
