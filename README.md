# Что сыграем?

Статический каталог импровизационных форматов. При открытии страницы сайт сразу показывает сохранённый каталог и проверяет обновления `data/formats.json` со своего адреса.

## Данные

Снимок содержит 269 форматов на момент переноса. Используются постоянные идентификаторы из первой колонки `id`; переименование формата не меняет его ссылку.

Порядок полей таблицы A–L: `id`, название, описание, модератор, зритель на сцене, реквизит, мебель, дополнительно, **Форма**, **Особенности**, **Подборки**, **Видео**. В каждой из трёх колонок классификации допускается несколько значений через запятую; пустая ячейка означает пустой список. «Видео» — обычный текст: ссылки или названия со ссылками, в том числе на нескольких строках. В карточке формата текст сохраняется, HTTP(S)-ссылки и адреса с `www.` открываются в новой вкладке. При пустом поле блок скрыт.

Новый JSON содержит `schemaVersion: 3`, дату `generatedAt` и массив `records`. У каждой записи есть `id`, `title`, `description`, `moderator`, `audienceOnStage`, `props`, `furniture`, `note`, `video` и независимые массивы `forms`, `features`, `collections`. Старые снимки и кэши без `video` читаются с пустым полем. Пустые признаки сохраняются как `null`. Параметры поиска и мебели вычисляются из текста при загрузке.

Импорт и браузер также поддерживают прежний снимок версии 2 с общим массивом `tags`: JAM, «Импровизация.Команды» и «Иностранные» относятся к подборкам; короткая и длинная форма — к форме. Кэш версии 2 читается и преобразуется в новую структуру. Данные версии 3 берутся строго из своих полей, без распределения по названиям.

Команда `npm run build` использует фиксированный `public/data/formats.json` для действующей публикации GitHub Pages.

Команда `Publish` сохраняет одобренные данные значениями на листе «Опубликовано». Новая сборка `npm run build:published` читает только этот лист через Sheets API, проверяет данные и сохраняет каталог в `dist/data/formats.json`. При ошибках чтения или данных сборка останавливается. Исходный JSON в репозитории остаётся прежним. Изменения рабочих ячеек попадут в сборку только после Publish.

Сайт опубликован на [www.improformats.ru](https://www.improformats.ru/). После обновления схемы проверены 265 форматов, отдельный фильтр подборок и HTTP-кэш с ETag; на первой публикации также проверено сжатие Brotli. Publish сохраняет снимок и запускает сборку через Deploy Hook; после успешной сборки данные появляются на сайте. Сборка также запускается при push кода в `main`. Вся цепочка проверена 25.10.2026. Дальнейшие шаги — в [плане](docs/plan.md).

В клиентской сборке нет адреса таблицы или ключей доступа. Готовый JSON каталога доступен посетителям сайта.

## Индексация

Основной адрес — `https://www.improformats.ru/`; он указан в `rel="canonical"` в [index.html](index.html). Параметры фильтров и выбранного формата относятся к тому же каталогу и используют этот же канонический адрес.

В `head` страницы также размещены метатеги подтверждения владения для Google Search Console и Яндекс Вебмастера. Не удаляйте их после подтверждения: поисковые системы могут повторно проверять права на сайт. Для Google используется ресурс с префиксом URL `https://www.improformats.ru/`.

В [vercel.json](vercel.json) настроены постоянные перенаправления (308) с `improformats.ru` и `impro-formats.vercel.app` на основной домен с сохранением пути и параметров запроса. Правила применяются после развёртывания на Vercel и ограничены этими двумя доменами. Локальный сервер, preview-домены Vercel и GitHub Pages продолжают работать по своим адресам; относительный `base: './'` сохранён.

[robots.txt](public/robots.txt) разрешает обход сайта и указывает на `https://www.improformats.ru/sitemap.xml`. [sitemap.xml](public/sitemap.xml) содержит только главную страницу: самостоятельных страниц форматов пока нет. Оба файла копируются Vite в `dist/` при обычной сборке и при сборке с опубликованным снимком.

После развёртывания проверьте доступность `/robots.txt` и `/sitemap.xml` на основном домене, а также перенаправления со старых адресов, в том числе ссылок с `?format=…`. Затем добавьте сайт и карту сайта в Google Search Console, Яндекс Вебмастер и Bing Webmaster Tools, подтвердив владение доменом.

## Кэш

Каталог хранится обычным JSON; сжатие при передаче выполняет хостинг. Последний проверенный набор сохраняется в `localStorage` и показывается сразу при следующем открытии. Затем браузер проверяет HTTP-кэш у сервера (`cache: 'no-cache'`). При прежнем ETag используем сохранённые записи без повторного разбора ответа и перерисовки.

Новую версию проверяем перед заменой кэша. При ошибке сети или данных остаётся сохранённый каталог. Если локальное хранилище недоступно или заполнено, сайт продолжает работать без сохранения между открытиями.

В кэше сохраняются исходные поля записей; поисковый текст и признаки мебели
вычисляются при чтении. Прежние кэши продолжают поддерживаться.

## Локальный запуск

Для отбора найденных агентом форматов есть отдельный [HTML-инструмент ревью](docs/format-review.md). Запрос `$import-formats Собери форматы из [источник]` запускает подготовку подборки через [скилл](.agents/skills/import-formats/SKILL.md), который затем ждёт результат ревью. Готовый файл также можно создать командой `npm run review:generate -- --input tools/format-review/example-batch.json` и открыть без сервера. Можно исправить поля, отметить записи и скопировать выбранное для таблицы или агента.

```bash
npm install
npm run dev
```

По умолчанию локальный сервер читает **рабочий лист «Все форматы» из Google-таблицы**
при каждом открытии или обновлении страницы. Правки существующих записей видны без Publish.
Для доступа нужны `GOOGLE_SHEET_ID` и ключ технического аккаунта в `.env.local`
(см. [.env.example](.env.example)); ключ используется только сервером и не попадает в браузер.

Другие варианты:

```bash
npm run dev:cached     # сохранённый public/data/formats.json, без обращения к таблице
npm run dev:published  # свежие данные листа «Опубликовано», после Publish
```

У трёх источников отдельные браузерные кэши. Последний успешно прочитанный каталог
выбранного источника может появиться сразу, пока идёт запрос свежих данных.
При ошибке таблицы сервер сообщает об ошибке и не подставляет файл из репозитория;
ранее загруженные данные остаются доступны. Причина ошибки выводится в терминале.
Локальный сервер только читает таблицу. Новые строки должны иметь постоянный `id`:
если он ещё пуст, сначала выполните Publish, который закрепит id в таблице.

Проверки:

```bash
npm test
npm run build
```

Браузерные проверки загрузки, прямых ссылок, клавиатуры, диалога и копирования
запускаются отдельно. При первом запуске установите Chromium:

```bash
npx playwright install chromium
npm run test:browser
```

Playwright сам запускает локальный Vite в режиме `dev:cached` и проверяет широкий и мобильный экраны.
Тесты используют небольшой каталог версии 3 и блокируют внешние запросы.
Эти же проверки включены в workflow GitHub Pages перед сборкой.
Яндекс.Метрика включается только в production-сборке вне localhost;
Vercel Analytics дополнительно требует окружение Vercel.

## Сборка с опубликованным снимком

Локальные настройки хранятся в `.env.local`, исключённом из Git. Образец — [.env.example](.env.example):

```dotenv
GOOGLE_SHEET_ID=SPREADSHEET_ID
GOOGLE_APPLICATION_CREDENTIALS=/path/to/service-account.json
```

Запуск:

```bash
npm run build:published
```

В [vercel.json](vercel.json) заданы команда `npm run build:published`, каталог `dist` и заголовок `Cache-Control: public, max-age=0, must-revalidate` для JSON. Заголовок разрешает хранить ответ, но требует проверять его свежесть. На опубликованном сайте проверены этот заголовок, ETag и ответ 304 на условный запрос.

В настройках сборки Vercel заданы `GOOGLE_SHEET_ID` и `GOOGLE_SERVICE_ACCOUNT_JSON` с содержимым JSON-ключа вместо локального пути. Эти переменные используются только сервером разработки и процессом сборки и не должны иметь префикс `VITE_`.

## Проверка доступа к Google Sheets

Проверить чтение листа «Опубликовано» от имени технического аккаунта:

```bash
npm run check:sheets -- /path/to/service-account.json SPREADSHEET_ID
```

Команда выводит аккаунт и количество форматов. Ключ и токен в журнал не попадают.
Ключ хранится локально и не должен попадать в Git или `public/`.
Доступ к локальной папке `ignore/` через сервер Vite закрыт.

## Скрипт таблицы

[Code.js](scripts/apps-script/Code.js) — исходник для привязанного к таблице Apps Script.
Он добавляет меню «Каталог», проверяет рабочий лист, сохраняет снимок по `Publish`
и затем отправляет POST-запрос в Deploy Hook Vercel.
После изменения файла его содержимое нужно перенести в редактор Apps Script.
Для публикации видео перенесите обновлённый скрипт и выполните Publish: снимок теперь включает колонку L «Видео».

Новой записи достаточно названия: колонку A (`id`) оставляют пустой. При Publish скрипт
проверяет данные и адрес хука, создаёт читаемый id из транслитерации названия и сохраняет его
в рабочем листе перед созданием снимка: «Новый формат» → `novyy-format`, «Тест» → `test`.
При совпадении добавляется первый свободный суффикс `-2`, `-3` и т. д.; учитываются все
существующие id и остальные новые записи. Название используется только при первой выдаче.
Существующие id не переписываются; дубликат или некорректный заполненный id останавливает публикацию.
Пустые строки пропускаются. Если формат создан копированием другой строки, его id нужно очистить.

Выданный id остаётся прежним при переименовании, перестановке строки и повторном Publish.
Если запись снимка или запрос в Vercel завершились ошибкой, уже сохранённые id сохраняются
для следующей попытки. Проверка всего каталога и настройки хука выполняется до записи новых id.

Для подключения в Vercel создаётся Deploy Hook `catalog-publish` для ветки `main`.
Его URL сохраняется в Apps Script: **Настройки проекта → Свойства скрипта**,
имя свойства — `VERCEL_DEPLOY_HOOK_URL`. URL не добавляется в код, Git или переменные браузера.
Затем нужно перенести обновлённый `Code.js` в Apps Script и сохранить.

При первом Publish Google запросит разрешение на внешний HTTP-запрос.
Отсутствующий или некорректный адрес хука останавливает Publish до изменения снимка.
Если запрос к Vercel не принят после сохранения, снимок остаётся сохранённым,
а сообщение об ошибке отделяет этот результат от запуска сборки. Секретный URL и ответ сервера не выводятся в журнал.
Успешное сообщение означает, что запрос на сборку принят; готовность сайта проверяется в Deployments.

## Фильтры

На широком экране фильтры расположены в компактной боковой панели с регулируемой шириной. Доступны форма, особенности и условия на сцене; переключатель «Есть видео» расположен последним. Раздел «Подборки» скрыт. На телефоне панель раскрывается над списком; кнопка «Показать N форматов» возвращает к результатам.

В форме выбирается одно значение; запись с несколькими формами подходит по любой из них. Все выбранные особенности должны совпасть. «Есть видео» оставляет записи с непустым полем `video`; пустые и отсутствующие значения не подходят. Между блоками условия объединяются через «И». Варианты фильтров берутся из данных каталога.

Выбранные ограничения видны над результатами и снимаются по одному. Поиск и фильтры сохраняются в URL, «Есть видео» — параметром `video=yes`. Ссылки с подборками по-прежнему поддерживаются: `collection` может повторяться, подходят форматы хотя бы из одной указанной подборки. Старые ссылки на JAM, «Импровизация.Команды» и «Иностранные» распознаются как подборки; новые ссылки сохраняют независимость трёх групп. Выбранные по ссылке подборки можно убрать над результатами.

## GitHub Pages

Старый способ публикации сохраняется до проверки замены на Vercel.

Workflow `.github/workflows/deploy-pages.yml` собирает и публикует `dist` при push в `main`. В настройках отдельного GitHub-репозитория выберите **Settings → Pages → Source → GitHub Actions**.

Проект использует относительный `base`, поэтому работает и на корневом домене, и по адресу вида `username.github.io/repository/`.
